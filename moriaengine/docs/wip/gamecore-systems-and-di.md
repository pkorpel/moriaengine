# GameCore systems and an incremental DI migration

**Recommendation:** start with the multi-model catalog inside UO data, not with a rewrite of `Main` or `ClassManager`. It has a real loader, one direct lookup in def finalization, and data that survives both world reload and script recompile. It lets us prove that an injected consumer and an unchanged static caller see the **same objects**.

This is a plan, not a description of an implemented DI container. The catalog and lifecycle traces below describe GameCore at `3f080d7c`, including the working-tree SharpConfig prototype where noted. The proposed boundaries are ownership boundaries, **not** proposed projects. Paths in the text are relative to `moriaengine/`; starting references are the [architecture overview](../current/01-overview/architecture-overview.md), [scripting pipeline](../current/02-engine-core/scripting-pipeline.md), and [persistence notes](../current/02-engine-core/persistence-and-saving.md).

## What must be ready, and why

These are the meaningful order constraints in [`MainClass.Init`, `RecompileScripts`, `ForgetAll`, `LoadAll` and `Exit`](../../GameCore/Main.cs). An arrow here means **the consumer needs the result**, not merely that the current `Main` calls two methods in that order.

1. **First boot:** `Main -> SteamMain -> Init` starts the aux link early. Touching `Globals` can read `steamengine.ini` even before the explicit `Globals.Init()` call. A missing file is written and exit requested; `Init` checks cancellation before compiling scripts. `build.ps1: Initialize-SteamEngineIni` relies on that exit. A test fixture currently has to claim the first touch by changing the process working directory.
2. **Compiled registrations -> script sections:** `CompilerInvoker.CompileScripts(true)` initializes core classes, builds or reuses the scripts DLL, loads it via `Assembly.LoadFile`, then initializes its classes. `ClassManager.InitClasses` runs class initializers on types with `Bootstrap`, invokes those hooks, then processes the types against the installed discovery callbacks. Generated holders, codecs and template glue arrive in that assembly. `AbstractDef.RegisterSubtype` registers both a section loader and a constructor. Having an empty type registry is not enough to parse an `[ItemDef ...]`.
3. **File contents + asset catalogs -> bound content:** `ScriptLoader.Load` reads `.scp` and `.def` through the same section reader. After the file pass, `ThingDef.LoadingFinished` resolves dupes/multi models, `Map.LoadingFinished` looks up named ground types, and `AbstractDef`, trigger holders and scripted dialogs finish deferred work. Some field/constant resolution is intentionally lazy unless `ResolveEverythingAtStart` is set. Do not model readiness as "every expression has been evaluated."
4. **Named defs + codecs + load hooks -> world -> indexes:** code-made plugin defs must already be registered when a save names them. `CheckCodeMadeDefs` is deliberately a **post-load diagnostic**, not the producer. `WorldSaver.TryLoad` reads globals and coordinator files, calls the `afterLoad` hook on the successful read path, **then** `ObjectSaver.LoadingFinished` runs delayed references and coordinator finalizers (`ThingSaveCoordinator` calls `On_AfterLoad`), then `Timer.LoadingFinished`. No save means a blank world; a recoverable bad load clears the partial world, restores script regions/global trigger links and retries (at most three attempts). `Map.Init` needs the resulting live things. On initial boot the listener binds **before** that indexing, then `ClassManager.InitScripts` processes Common types and calls late script `Init` methods. `PluginDef.Init()` itself is empty.
5. **Running and saving:** the host sets Running, fires `@startup(true)`, checks for changed sources and starts the timer thread. There is no single polling gameplay loop: packets, timers and sync workers enter through the game lock. `Globals.TrySave`/`SaveInBackground` lead to `WorldSaver`: finish any previous write, run hooks and format world data, then write the buffers. Background disk I/O is not permission to enumerate a mutable world off-lock. `PendingSave.Finish` delivers `afterSave` once under the lock; script hooks can choose paths/streams and rearm an autosave.
6. **Compiled rebuild:** `Globals.Resync` checks C# changes first. Recompile saves; if saving fails it does **not** discard the world. Otherwise `@shutdown(false)`, backup character UIDs, clear world/timers and forget script registrations. `LoadAll` compiles again, loads content, reattaches global groups, loads the world, relinks clients, indexes maps, runs late initialization and `@startup(false)`. A failed compile enters `AwaitingRetry`; the aux command path can retry without killing the process. This is not identical to first boot: no new listener, no MUL reload, no second timer thread; `ScriptedLocResxBridge.RegisterAll` is explicit on boot but not in `LoadAll`. Characterize that difference rather than silently normalizing it.
7. **Shutdown:** `.exit`/console Enter use `SaveAndExit` when running; `.exitnosave` skips the new save. `Exit` finishes an already pending write, stops game/aux endpoints, fires `@shutdown(true)` if there is a global holder, then clears timers and marks the host dead. Do not bury save policy in `Dispose()`.

### Text resync is an identity-preserving edit, not a new scope

For a concrete example, edit one `[events ...]` section. [`ScriptFileCollection.GetChangedFiles`](../../GameCore/ScriptFilesCollection.cs) finds new files and calls `ScriptFile.CheckChanged` on tracked files. Changed metadata or disappearance calls `Unload()` on **that file's** `IUnloadable` entries. Detection itself mutates state. [`ScriptedTriggerGroup.Unload`](../../GameCore/LScript/ScriptedTriggerGroup.cs) clears its trigger dictionary and marks the group unloaded; it does not remove its identity from `AbstractScript.byDefname`. `ScriptLoader.Resync` rereads existing changed files. `GetNewOrCleared` finds the old group; `Load` installs **new `LScriptHolder` bodies on the same group** and unmarks it. A holder already referencing the group sees the new behavior. An unchanged file's group and bodies are not rebuilt. A removed group is not silently replaced with an empty, ready group.

Defs have a related but stricter rule: [`AbstractDef.LoadFromScripts`](../../GameCore/AbstractDef.cs) resolves primary/alternate names, refuses a type change or duplicate live definition, and reuses/re-registers the compatible unloaded instance. [`FieldValue.SetFromScripts`](../../GameCore/FieldValue.cs) updates the default without overwriting a manually changed current value. `LScriptMain.LoadAsFunction` likewise recompiles an unloaded named function holder in place. Keep file provenance, aliases and object identity; do not dispose the script or world scope on text edits. Today's resync is **not** an atomic transaction: unloading precedes rereading, and section errors can be logged and skipped.

## Proposed composition and lifetimes

Use `GameCore/Main.cs: MainClass.SteamMain` as the production composition root and a test host factory as a second root. Register **systems** explicitly there or in named modules. Constructors take the capabilities they use; no container in entities, generated holders or scripts. Discover **contributions** (config descriptions, section handlers, generated codecs, def types, compiled functions) in explicitly chosen assemblies. A discovered `ItemDef` is content/factory input, not an independently started service.

| Proposed owner | Owns | Boundary rule |
|---|---|---|
| Process host | Clock, execution gate, config source, client-data catalogs/readers, listeners, aux link and worker lifetimes | May route to the **currently ready** world/generation at dispatch time. Never constructor-inject a particular character, script delegate or generation's type table into a process singleton. |
| Compiled-script generation (child of process) | Loaded assembly, type/factory/codec contributions, function/def/trigger/dialog indexes, changed-file tracker, script-owned subscriptions | May use process services. Mutable text content stays *in* this generation across resyncs. Core registrations survive as a baseline, not as copies of script entries in the root. |
| World or load attempt (child of generation) | Global tag holder, UID/name stores, entities/plugins, dynamic map membership, world timer registrations | Can reference generation defs. Discard a failed attempt without disposing script content. Script-created region descriptions must be replayable into a new world; a generation must not cache the world's live region instances. |
| Connection (under process); save/load operation (under its world/attempt) | Connection owns transport/session state; operation owns reference maps, pending callbacks and buffers | These are **not siblings with interchangeable lifetime**. Detach the connection's world binding before disposal; finish a pending save, including its callback, before releasing the world. |

**Readiness is not a DI lifetime.** For example, construct a multi-data loader with options and a reader, load it, then publish an `IMultiModelLookup` to def finalization. For scripts, expose a registration sink during discovery and a lookup once required contributions are installed. Each participating system declares its concrete prerequisites and what its load returns; the host runs the requested dependency closure and unwinds completed work in reverse on failure. Keep an explicit distinction between *registered*, *populated* and *safe to dispatch gameplay*. Parsers, value codecs and heap algorithms need no `Init/Deinit` ceremony. Don't start threads in constructors. A test can supply an already-populated fake lookup or a manual clock and initialize just its consumers.

**Container choice:** use ordinary constructor calls for the first slice. If moving to a container, prefer **Autofac over writing a container**: explicit modules, constructor injection, child-scope registrations and disposal fit a generation with different discovered types. Built-in .NET DI is an alternative for a fixed registration set; its ordinary scopes don't add new service registrations per child. Neither choice does domain readiness or text resync for us. Autofac's [`IStartable`](https://autofac.readthedocs.io/en/latest/lifetime/startup.html) is useful for a one-time startup action; it does not express "all files read, postponed defs bound, now resolve saved references" or rerun on an in-place edit. For physical unloading evaluate [`BeginLoadContextLifetimeScope`](https://autofac.readthedocs.io/en/latest/advanced/scopes-loadcontexts.html) with a **collectible** .NET load context. Disposing the scope alone does not unload today's `Assembly.LoadFile` assembly.

**Configuration boundary:** keep the actual filename `steamengine.ini`. The prototype's [`GameConfiguration.Bind`, `DefaultIni`, `WriteNew`](../../GameCore/Configuration/GameConfiguration.cs) discovers section classes, applies property defaults and writes a new file via a temporary file and non-overwriting move. `DefaultIni` currently adds a section **per type**. Instead discover consumer schemas as metadata before starting systems. Group by INI section and key, emit **one** `[files]` with the union of keys, and project only the requested keys into each consumer's options. For example UO data may read `mulPath`, `writeMulDocsFiles`, `readBodyDefs` and `generateMissingDefs`; saving may read `savePath` and `autosaveMinutes` from the very same section. Shared keys need one canonical default/type; reject conflicting contributions with both owners named. Existing files get missing defaults **in memory only**; adding missing keys on disk would be a separate explicit operation. Preserve legacy spellings/conversions and unknown content. A missing file gets the full commented default and a clean exit **before** compilation/world work. Do not construct the systems just to enumerate their defaults.

When extraction is premature, an injected adapter may read the existing owner first; it must not maintain a mirror. No step requires a new `.csproj`.

### Risks and decisions before expanding the migration

- **Logical unload is not CLR unload.** `ClassManager.ForgetScripts` filters some discovery lists but doesn't clear `registerTGmethods`; `MemberWrapper` caches reflection objects; `AbstractAccount.CreateGameAccountFunction` and packet handlers cache `ScriptHolder`s. `DynamicAssemblyResolver` in Common resolves by simple name across loaded assemblies. Move or invalidate these references, including generated wrappers, rather than relying on `CollectGarbage`. `ActivityGrid.ForgetScripts` is an example of explicitly dropping script delegates.
- **A socket surviving does not mean its world binding is safe.** `GameState.BackupLinksToCharacters` saves a UID, not a detached session; `RelinkCharacter` gets the new character/account and clears gump dictionaries. The `-1` case has no character to relink, and pending target delegates are separate fields. Define what a logged-in client at character selection, or a client with a pending target, sees on rebuild. Do not accidentally dispatch into its previous world.
- **Two apparent cycles have smaller cuts.** Persistence need not construct scripts: inject a populated codec/name lookup and supply hooks for that operation. Geometry need not construct `Map`: return multi descriptions; maps place live components later. Similarly, register timer entries before starting dispatch. These splits avoid forcing scripts, maps, timers and persistence into the same change.
- **Decisions to make deliberately:** whether changing the INI during a world reset should still take effect; whether config defaults may come from reloadable scripts (first-run output currently precedes compiling them); whether physical assembly collection is required or logical replacement suffices. Preserve existing behavior until each change has a test and an explicit decision.

## First implementation slice: the multi-model catalog

In [`MainClass.Init`](../../GameCore/Main.cs), replace **only** the `MultiData.Init()` call between `SoundMul.Init()` and `ScriptLoader.Load()`. Construct a process-owned multi catalog from `mulPath`, `useMultiItems`, the report flag and report destination. Have its loader return the model lookup, keeping I/O out of the constructor. Pass the lookup through the content load to [`ThingDef.LoadingFinished`](../../GameCore/ThingDef.cs), which sets `idef.multiData`; use the **same** lookup when `LoadAll` reloads defs. Keep `MultiData.GetByModel` delegating to that catalog while needed. [`Map.AddMulti`](../../GameCore/Regions/Map.cs) continues to materialize per-world components from the def. No new world, config writer, script generator, thread or project in this slice.

Use a tiny `multi.idx`/`multi.mul` fixture with one empty slot and one populated slot: the model is `0x4000 + slot`, positive-flag parts retain their signed offsets, and zero-flag parts are skipped. Also characterize disabled/missing input and optional docs output: the current reader distinguishes a disabled feature, missing files, and a read that ends partway through; don't silently change startup policy. Verify that a loaded multi def and the legacy lookup return the same description and that placing it puts components at the expected coordinates. A second test host with a different fixture must not inherit the first catalog. That demonstrates explicit registration, readiness, compatibility and test isolation before applying the same pattern to tile/display data.
