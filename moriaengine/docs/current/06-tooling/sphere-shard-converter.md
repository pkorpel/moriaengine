# SphereShardConverter

A one-time, offline migration tool (`SphereShardConverter/`, namespace
`SteamEngine.Converter`) that converted the original Erebor shard's real Sphere content
into moriaengine's own `.def`/`.scp` format. Not part of the running server - it was run
once to produce the `scripts/converted/` tree, which is what the live engine actually
loads. See [Architecture overview](../01-overview/architecture-overview.md) for where
this fits among the other top-level projects.

## What it does

`ConverterMain` (`SphereShardConverter/Main.cs`) reads raw Sphere source files from a
`convert/` input folder and writes converted output into `scripts/converted/`
(`ConverterMain.convertToPath`). `ConvertedFile` (`ConvertedFile.cs`) represents one
output file - it strips Sphere's own `sphere_`/`sphere_d_` filename prefixes
(`GetNewFilename`) and writes a `//Automatically generated by SteamEngine's converter`
header before dumping each contained `ConvertedDef`.

The actual per-block conversion logic is split by content kind: `ConvertedItemDef`,
`ConvertedCharDef`, `ConvertedThingDef` (the shared base for both), `ConvertedTemplateDef`,
`ConvertedRegion` - each knows how to translate one Sphere block type's own field/trigger
syntax into this engine's equivalent `.def`/`.scp` shape. `ConvertedConstants` holds
cross-reference tables (defname remaps, known-unsupported-field lists) the per-kind
converters consult.

## Why its output needed real content fixes later, not just a conversion pass

The converter is a blunt instrument by necessity - it couldn't verify that a Sphere
value or reference it couldn't resolve (an unknown macro, a renamed defname, a field
this engine doesn't model yet) was actually *safe* to drop; it just drops what it can't
convert and moves on, sometimes silently. This produced several real, confirmed content
gaps discovered well after the conversion itself, documented across multiple gameplay-
system pages rather than here:

- [Races & nations](../04-gameplay-systems/races-and-nations.md) - 5 of 9 profession
  starting-equipment templates were missing items the converter couldn't resolve
  (Craftsman's entire tool kit, several weapons, a typo'd crossbow defname).
- [Professions](../04-gameplay-systems/professions.md) - a systematic
  `Cooking`/`Fishing` starting-value drop affecting every profession's `.def`.
- [Housing](../04-gameplay-systems/housing.md) - house deeds' original converted content
  referenced the target house via `RESOURCES` (crafting's consumption-list syntax), which
  doesn't fit what a deed actually needs - the converted content for this feature was
  entirely commented out, not usably converted.

**General lesson for working with `scripts/converted/` content**: a `//guessed by
Converter`-style comment, a value that doesn't match the original Sphere source when
checked, or content that's entirely commented out are all real signals the converter
couldn't do a faithful job for that specific piece - worth cross-checking against the
original pre-conversion Sphere source (not just the wiki or this engine's own converted
copy) before trusting it, the same pattern that resolved several of the gaps above.

## Current status

Not actively maintained or re-run - the conversion already happened, and
`scripts/converted/` is now just ordinary (if imperfect) game content like any other
`.def`/`.scp` file under `scripts/`. This project would only be touched again if a
wholesale re-conversion from fresh Sphere source were ever needed.
